# Что дальше с Братиком

## Версия 0.3: надёжное продолжение разговора

Основа перенесена из сохранённого архива `bratik-core-v0.2.zip`. Внутри старого архива package.json и README ещё называли её 0.1; текущая версия согласована как 0.3.0.

Сделано:

- История из SQLite восстанавливается в интерфейсе; предыдущие сообщения загружаются порциями.
- Повтор одного запроса использует его идентификатор. Завершённый ответ возвращается повторно без новой генерации и дублирования переписки.
- Ollama, наличие модели и поддержка текстового разговора проверяются отдельно от сервера приложения.
- Новые предложения памяти проходят просмотр, редактирование и подтверждение. Старая активная память сохраняет статус, неактивная остаётся забытой.
- Подтверждённые предпочтения, решения, задачи и полезные выводы можно использовать в следующих разговорах. Это контекст модели, а не изменение её весов.
- Очередь извлечения памяти хранится в базе, прерванная обработка возобновляется при следующем запуске. Ошибочные задания можно повторить из интерфейса.
- Перед обновлением старой схемы создаётся резервная копия. Есть отдельная команда backup и JSON-экспорт данных.

## Проверка на целевом компьютере

Автоматические проверки используют настоящую SQLite и HTTP-сервер, а ответы Ollama подменены контролируемым локальным сервером. Они проверяют работу приложения при успехе и сбоях.

Перед ежедневным использованием новой версии на Mac нужно выполнить `npm run doctor`, затем реальный разговор с установленной моделью. Отдельно проверить восстановление страницы и кнопки памяти в браузере. Скорость, потребление памяти и качество ответов зависят от выбранной модели и компьютера; автоматические проверки их не измеряют.

## Следующие этапы

1. **Голос поверх этого же ядра.** Найти актуальные исходники отдельного голосового прототипа, проверить его провайдера и формат диалога. Подключить его к общей истории и памяти. В версии 0.3 голосовых элементов нет.
2. **Контексты проектов.** Добавить несколько разговоров и явное состояние проекта: цель, решения, открытые задачи, следующий шаг. Сейчас история общая, один продолжающийся разговор.
3. **Более точная память.** Локальный семантический поиск и связь «новая запись исправляет старую». Сейчас факты выбираются по словам, а забывание блокирует совпадающие и ранее отредактированные формулировки. Другую перефразировку пользователь проверяет отдельно.
4. **Потоковый ответ и остановка.** Показывать текст по мере генерации и добавить отмену с понятным состоянием незавершённого запроса.
5. **Инструменты выполнения.** Только после определения конкретных действий и границ доступа. Текущее ядро не читает пользовательские файлы, не запускает команды и не управляет приложениями от имени модели.

Эти пункты — план дальнейшей разработки; они не работают в текущей версии и не выполняются в фоне после остановки приложения.
