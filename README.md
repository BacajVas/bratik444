# Bratik Core 0.3

Братик — персональный напарник с историей разговора и управляемой памятью. Приложение работает на Node.js и SQLite, ответы получает через Ollama на этом компьютере. OpenAI API, ключи и npm-зависимости не нужны.

## Что даёт v0.3

- Один постоянный диалог: после перезагрузки страницы возвращаются последние 60 сообщений, более ранние можно подгрузить.
- В запрос к модели входят последние 20 сообщений контекста и подходящие подтверждённые воспоминания. Вся история в базе и текущий контекст модели — разные вещи.
- Новые полезные факты, предпочтения, решения, долгосрочные задачи и явно сформулированные пользователем уроки сначала попадают в предложения памяти. Ты выбираешь, что подтвердить.
- Неподтверждённая память не используется в ответах. Забытые и отклонённые записи не включаются в контекст и не активируются повторным автоматическим извлечением.
- Выбор модели из списка Ollama, диагностика отсутствующей модели и понятные ошибки соединения/ожидания.
- Сохранение состояния запросов и повтор неудачного запроса без дублирования пользовательской реплики.
- Разбор диалога на предложения памяти выполняется через сохраняемую очередь. Незавершённая работа восстанавливается после перезапуска; временный сбой можно повторить.
- Резервная копия SQLite отдельной командой и копия перед обновлением схемы старой базы.

Это память приложения и отбор контекста, **не самообучение модели**: веса Ollama не меняются. Задача, сохранённая в памяти, не становится автоматически выполненной задачей или напоминанием. Голос, управление компьютером и внешние инструменты в эту версию не входят.

## Первый запуск на Mac

Понадобятся [Node.js](https://nodejs.org/en/download) **24 или новее**, [Ollama](https://ollama.com/download) и установленная модель. Подходящая модель и скорость зависят от памяти и процессора компьютера.

1. Распакуй проект в отдельную папку. Открой Terminal, набери `cd `, перетащи папку проекта в окно Terminal и нажми Enter. В этой папке должны находиться `package.json` и `server.mjs`.
2. Проверь Node и открой приложение Ollama:

   ```bash
   node --version
   ollama list
   ```

3. По умолчанию выбран `gpt-oss:20b`. Если этой модели нет и она подходит твоему компьютеру, загрузи её:

   ```bash
   ollama pull gpt-oss:20b
   ```

   Если уже есть другая модель, её можно выбрать в интерфейсе. Чтобы задать её до запуска, создай `.env` по разделу ниже и поменяй `BRATIK_MODEL` на точное имя из `ollama list`.

4. Запусти диагностику, затем приложение:

   ```bash
   npm run doctor
   npm start
   ```

5. Открой **http://127.0.0.1:3044**. Terminal с сервером оставь открытым. Остановка — **Ctrl+C**.

`npm install` не требуется: внешних зависимостей нет. Диагностика проверяет доступность Ollama и выбранную модель; она не запускает генерацию и не создаёт пустую базу. Если модель ещё не готова, приложение всё равно можно открыть через `npm start`, чтобы посмотреть диагностику и выбрать установленную модель.

## Настройки

Чтобы изменить стандартные значения, **один раз** создай `.env` из примера. Если `.env` уже есть, отредактируй его, не заменяя содержимое командой копирования.

```bash
cp -n .env.example .env
```

`npm start`, `npm run doctor` и `npm run backup` читают `.env` из папки проекта. Уже заданные переменные Terminal имеют приоритет над `.env`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3044` | Порт интерфейса; сервер слушает только `127.0.0.1`. |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Локальный адрес Ollama. Внешние серверы эта версия не принимает. |
| `BRATIK_MODEL` | `gpt-oss:20b` | Начальная модель, если выбор ещё не сохранён в базе. |
| `BRATIK_TIMEOUT_MS` | `180000` | Ожидание генерации в миллисекундах; допустимо от 1000 до 600000. |
| `BRATIK_DB_PATH` | `bratik.db` | Путь SQLite. Относительный путь считается от папки проекта; можно указать абсолютный. |

**Выбор модели в интерфейсе сохраняется в базе и имеет приоритет над `BRATIK_MODEL`.** Поэтому диагностическая команда тоже проверяет сохранённую модель. Изменения `.env` применяются после перезапуска Bratik.

## Обновление со старой версии без потери истории

Старая папка и база должны остаться доступными до проверки новой версии. Не запускай две версии одновременно с одним файлом базы.

1. Останови старый Bratik через **Ctrl+C** и дождись возврата приглашения Terminal.
2. Распакуй v0.3 в **новую отдельную папку**, пока не запуская её. Старые исходники, базу и резервные копии не удаляй.
3. Сделай резервную копию базы. Если в установленной версии уже есть команда, выполни в её папке:

   ```bash
   npm run backup
   ```

   Если команды ещё нет, перейди в новую папку проекта через `cd` и сделай копию до первого запуска, указав старый файл:

   ```bash
   BRATIK_DB_PATH="/полный/путь/к/старой/папке/bratik.db" npm run backup
   ```

   Подставь настоящий абсолютный путь. Команда откроет источник только для чтения и создаст согласованную SQLite-копию без миграции.

   Вариант через Finder: скопируй **закрытую старую папку целиком**, включая находящиеся рядом `bratik.db-wal` и `bratik.db-shm`, если они остались. Не копируй один `bratik.db` из работающего приложения: часть свежих данных может находиться в WAL.

4. Выбери расположение рабочей базы:

   - Для независимой проверки новой версии скопируй созданный файл `.sqlite` в новую папку под именем `bratik.db`. Старый оригинал останется отдельным.
   - Либо в новом `.env` задай `BRATIK_DB_PATH="/полный/путь/к/старой/папке/bratik.db"`. Тогда новая версия продолжит работу непосредственно с прежней базой.

5. Если менял характер Братика, перенеси свой текст в `bratik-personality.local.md` новой папки.
6. В новой папке запусти `npm run doctor`, затем `npm start`. Первый запуск создаст резервную копию старой базы **перед миграцией**. После успешного запуска проверь историю и вкладку памяти.

При миграции прежние записи с `active=1` остаются подтверждёнными, а `active=0` становятся забытыми. Сохранённые ранее данные не переводятся автоматически в новые предложения. Новое извлечение в v0.3 уже требует подтверждения.

Если потребуется вернуться к старой версии, останови новую и используй сохранённую копию **до миграции**. Не открывай обновлённую базу старой программой. Пока проверяешь новую версию, не смешивай переписки из двух разных копий.

## Резервное копирование и перенос

```bash
npm run backup
```

Команда создаёт файл `backups/<имя>-<дата>-<UUID>.sqlite` рядом с выбранной базой. У каждого файла уникальное имя; прежняя копия не перезаписывается. Используется SQLite Backup API, после копирования выполняется `PRAGMA quick_check`. Команда не создаёт исходную базу, если той ещё нет, и не зависит от запущенного сервера Bratik или Ollama.

Копия включает таблицы истории, памяти, очереди и настроек, которые есть в базе. Она не включает модель Ollama, `.env` и файл характера: их переноси отдельно. Для восстановления останови Bratik, возьми копию базы под новым именем и укажи её через `BRATIK_DB_PATH`; исходный файл оставь до проверки результата.

В интерфейсе доступен экспорт данных для просмотра и переноса информации. Экспорт не заменяет полноценную SQLite-копию для восстановления состояния приложения.

База, её копии, экспорт и `.env` содержат личные сведения. Они исключены из Git вместе с `bratik-personality.local.md`. Это защита от случайного коммита, а не шифрование диска.

## Как работает память

После ответа отдельный фоновый запрос предлагает сведения, которые могут пригодиться дальше. Например: «для моего проекта нужен русский вокал», «мы решили использовать SQLite», «нужно закончить монтаж» или сформулированный пользователем вывод из ошибки.

В предложении можно проверить содержание и источник, подтвердить полезное либо отклонить лишнее. Модель может ошибаться при извлечении: наличие предложения не делает его фактом. Уже подтверждённое воспоминание можно забыть.

«Забыть» означает исключить запись из памяти, используемой в ответах. В базе остаётся отметка, чтобы такое же автоматическое предложение не воскресило её. Исходная реплика также может сохраняться в истории и старых резервных копиях. Это не команда полного стирания всех следов с диска.

Очередь извлечения сохраняется в SQLite. Если Ollama недоступна или завершился процесс, предложение может появиться позже после успешного повтора. Количество предложений поэтому не обязано измениться одновременно с основным ответом.

## Характер Братика

Базовый характер находится в `bratik-personality.md`. Для своего варианта создай рядом файл `bratik-personality.local.md`: он имеет приоритет и не входит в Git.

Например, можно скопировать базовый файл, затем изменить копию:

```bash
cp -n bratik-personality.md bratik-personality.local.md
```

После редактирования перезапусти приложение. Инструкции характера влияют на ответы, но не добавляют доступ к компьютеру и не меняют веса модели.

## Что означает «локально»

Bratik слушает loopback-интерфейс и обращается к локальному HTTP-серверу Ollama. История и память хранятся в выбранном файле SQLite. Однако **адрес `127.0.0.1` не гарантирует локальную генерацию**: сам Ollama умеет направлять запросы облачным моделям, в том числе через алиасы.

Для режима только на компьютере выбери загруженную локальную модель и отключи облачные функции **в самом Ollama**. Для приложения Ollama на macOS:

```bash
launchctl setenv OLLAMA_NO_CLOUD 1
```

После этого полностью заверши Ollama через Quit и открой заново. Если запускаешь Ollama непосредственно из Terminal, используй отдельный запуск:

```bash
OLLAMA_NO_CLOUD=1 ollama serve
```

Выбери способ, соответствующий своему запуску Ollama. Не запускай второй `ollama serve` поверх уже работающего сервера. Добавление `OLLAMA_NO_CLOUD` только в `.env` Bratik **не изменяет окружение уже запущенного Ollama**. Альтернатива — настройка `disable_ollama_cloud` в конфигурации Ollama; она описана в официальном FAQ.

## Если что-то не запускается

| Симптом | Что проверить |
|---|---|
| `node`/`npm` не найден или Node ниже 24 | Установить Node 24+, открыть новый Terminal и проверить `node --version`. |
| Ollama недоступна | Открыть Ollama; проверить `OLLAMA_URL`; выполнить `npm run doctor`. |
| Модель не найдена | Посмотреть `ollama list`; выбрать установленную модель в интерфейсе либо загрузить нужную. |
| Изменение `BRATIK_MODEL` не помогает | Модель уже сохранена в SQLite. Изменить её в интерфейсе. |
| Долгое ожидание или timeout | Первый запрос включает загрузку модели. Выбрать модель, подходящую памяти компьютера, либо увеличить `BRATIK_TIMEOUT_MS` в допустимых пределах. |
| Порт занят (`EADDRINUSE`) | Остановить прежний Bratik или изменить `PORT`; не запускать две версии с одной базой. |
| База заблокирована | Остановить второй экземпляр или внешнюю программу, удерживающую базу. |
| Диагностика говорит, что базы нет | Для первого запуска это нормально. `npm start` создаст базу; doctor и backup пустой файл не создают. |
| После обновления история пустая | Сверить путь базы в диагностике и `BRATIK_DB_PATH`; не удалять прежний файл. |
| Предложения памяти ещё не появились | Проверить состояние фонового разбора и Ollama; очередь выполняется отдельно от основного ответа. |

## Проверки проекта

```bash
npm test
```

Автоматические тесты используют временные базы и имитацию HTTP-ответов Ollama. Они проверяют код приложения, а не качество выбранной модели, скорость конкретного Mac или визуальную работу браузера. Реальная генерация Ollama, запуск на Mac, браузер и голос не заявлены как проверенные этим набором тестов.
